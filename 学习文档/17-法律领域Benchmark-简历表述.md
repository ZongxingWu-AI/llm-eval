# 法律领域 Benchmark 项目：简历与面试表述

> 用途：将本项目包装为“大模型评测工程闭环”项目，适用于大模型评测工程师、LLM 数据/质量、Benchmark 研究和评测平台岗位。
>
> 使用原则：只写已经能够用代码、运行目录或报告证明的内容；`X` 占位指标必须在正式题集和模型评测完成后替换。

## 一、项目名称与技术栈

**法律领域大模型评测 Benchmark 与自动化评测流水线**  
个人项目｜端到端独立设计与实现

**技术栈：** Python、LLM-as-a-Judge、Benchmark、Rubric、JSONL、JSON Schema、OpenAI-Compatible API、数据校验、Excel 报告

## 二、简历推荐版本

- 面向法律垂直领域大模型评测，独立设计并实现“真实民事一审判决书 → 结构化案件 → 评测题集 → 模型回答 → 自动评分 → 评测报告”的端到端流水线，覆盖数据清洗、信息抽取、题目生成、人工审核、数据集发布和批量评测等环节。

- 基于 **50 份真实民事一审判决书** 构建法律 Benchmark，覆盖合同纠纷、劳动争议、侵权责任、婚姻家庭/继承、物权纠纷等 **5 类民事场景**；围绕事实抽取、争议焦点识别、规则适用、证据评价、裁判结果预测、金额计算和合规拒答等能力设计评测任务，形成结构化题目、参考答案、Rubric 和来源证据。

- 设计案件级 `dev / calibration / test` 数据划分机制，保证同一案件的多道题不跨数据集；通过 JSON Schema、受控 Taxonomy、来源章节与原文证据校验、哈希 Manifest 和重复检查，提升题集的可追溯性、可复现性和数据质量。

- 实现支持 `rule / redline / rubric_judge` 三类评分方式的法律回答 Grader：针对必答点、扣分项、拒答关键词和开放式 Rubric 进行分层判分，统一输出 `PASS / REVIEW / REJECT`；批量记录模型回答、评分理由、错误信息、延迟、Token 消耗和运行元数据，并生成 Markdown/Excel 评测报告。

## 四、面试中的项目主线

### 1. 问题定义

法律回答不能只看文本相似度，还要判断事实是否正确、法律规则是否适用、证据依据是否充分、金额计算是否正确，以及是否触发高风险错误。因此项目采用“结构化案件 + 任务化题集 + 分层 Grader”的设计，而不是简单的问答相似度评测。

### 2. 数据设计

从真实判决书中保留案件全文、案件主体、裁判理由、判决主文和来源位置，构建 `raw → parsed → cleaned` 的数据生命周期；题目中的参考答案和 Rubric 通过来源章节、原文证据进行追溯，避免生成脱离上下文的问答对。

### 3. 题集设计

将案件拆解为事实抽取、争议焦点识别、法律规则适用、证据评价、裁判结果预测、金额计算和合规拒答等能力任务，为每道题配置参考答案、必答点、扣分项、风险等级和来源证据，并在发布前执行字段、标签、证据和 split 校验。

### 4. 评分设计

- `rule`：适用于答案关键点比较确定的结构化或半结构化任务。
- `redline`：适用于合规拒答、风险提示和禁止性表达检查。
- `rubric_judge`：适用于开放式法律论证，由裁判模型依据参考答案和 Rubric 进行判断。

三类评分统一输出 `PASS / REVIEW / REJECT`，同时保留评分理由和命中的评分点，便于错误定位和人工复核。

### 5. 可靠性控制

通过案件级切分避免同案泄漏；通过受控 Taxonomy 和 JSON Schema 约束题目字段；通过来源证据、哈希 Manifest、运行元数据和错误文件保证结果可追溯、可复现、可定位。

### 6. 结果分析

不只报告整体通过率，还应按数据集 split、任务类型、案件类型、评分方式和错误类型分析模型短板，区分模型能力问题、题目质量问题、评分器问题和模型调用/解析问题。

## 五、当前仓库中已经可以确认的事实

截至 **2026 年 8 月 25 日**，仓库已有：

- 50 份已选择、解析和结构化的案件；
- 5 类法律纠纷分类，每类当前选择 10 份案件；
- Taxonomy、Schema、清洗、抽取、题集构建、案件级切分、评分器和批量评测代码；
- `PASS / REVIEW / REJECT` 三档评分逻辑；
- 运行结果、错误记录、报告、运行元数据和可选 Excel 导出的输出设计。

当前已落盘的 `parsed` 和 `cleaned` 数据各为 50 条；`drafts`、`releases` 和 `results` 目录目前主要是说明文件。因此在完成候选题审核、正式题集发布和模型批量评测之前，不应在简历上声称已经获得模型准确率、评分一致率或完整评测结果。

## 六、不要写成的表述

除非有对应实验或训练证据，否则不要写：

- “模型准确率提升 30%”；
- “显著提升模型效果”；
- “达到业界领先水平”；
- “解决了法律大模型幻觉问题”；
- “训练/微调了大模型”。

更稳妥的写法是：

- “构建并验证法律领域评测流程”；
- “定位模型在事实抽取、规则适用、证据评价和合规拒答上的错误分布”；
- “设计分层评分器并保留可解释的评分理由”；
- “为后续模型优化提供按能力维度拆解的评测依据”。
